Third-party components
======================

AMISCE / SCEWIN_64.exe, amifldrv64.sys, amigendrv64.sys  (bundled)
------------------------------------------------------------------
Roch NVRAM does not talk to the firmware itself. Every read and every write
goes through AMISCE, the AMI Setup Configuration Extractor, shipped here as:

  scewin/SCEWIN_64.exe      AMISCE Utility, Ver 5.05.01.0002
  scewin/amifldrv64.sys     AMI kernel driver
  scewin/amigendrv64.sys    AMI kernel driver

  Copyright (c) American Megatrends International, LLC.

These are proprietary AMI binaries, and the two .sys files are signed kernel
drivers. They are not covered by this project's GPL-3.0 licence, no part of
them was written here, and nothing in this repository grants any right to them.
AMI distributes AMISCE to its customers rather than to the public; the copies
here came from a vendor package that includes it -- MSI Center ships one.

They are bundled for convenience. This project does not establish their
authenticity or its own right to redistribute them, and anyone redistributing
Roch NVRAM should satisfy themselves about that separately. If you would rather
not take them on trust, delete the scewin/ folder and drop in the three files
from a source you do trust: the paths and the expected filenames are in
src/backend.rs, and the application checks for all three and
refuses to run live without them.

The drivers are copied to %LOCALAPPDATA%\NVRAM\runtime on first use and loaded
by SCEWIN itself. Roch NVRAM does not install a service and does not load them
directly.

SCEHUB  (followed, not bundled)
-------------------------------
  https://github.com/ab3lkaizen/SCEHUB  -- ab3lkaizen

SCEHUB packages AMISCE with two batch files, Export.bat and Import.bat, which
run it as "/o /s nvram.txt" and "/i /s nvram.txt": read the NVRAM to a text
file, edit the text file, write it back. That is the workflow this program is
built around, and the Export and Import buttons are those two halves.

Roch NVRAM adds a review step between them. Import matches the queued changes
against a fresh export, refuses to continue when anything moved, takes a backup
and verifies every value afterwards -- Import.bat writes the file as it stands.

No file from SCEHUB is included here, and it is not needed to run this.

Rust crates  (dependencies, compiled into the executable)
--------------------------------------------------------
The window is egui/eframe; the rest is a handful of common crates (regex,
serde, serde_json, indexmap, sha2, chrono, image, rfd, open, winreg,
windows-sys). They are fetched from crates.io by Cargo rather than committed
here, and their exact versions are pinned in Cargo.lock. Almost all are
licensed under MIT and/or Apache-2.0; a few are Zlib, ISC, BSD, or
Unicode-3.0. All of these permit use from a GPL-3.0 program. `cargo tree`
lists the crates, and each crate's licence is in its published package.

egui's built-in fonts are embedded as fallbacks (epaint_default_fonts):
Ubuntu-Light under the Ubuntu Font Licence 1.0, Hack under MIT, and
Noto Emoji and emoji-icon-font under the SIL Open Font Licence 1.1. On
Windows the interface itself uses Consolas and Segoe UI Symbol, which are
read from the system at run time and not redistributed.
